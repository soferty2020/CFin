# CFin — Roadmap

> **Статус на 2026-10-30:** P0 (#1), P1 (#2), P2 (#3) и отдельная задача #10 закрыты. Открыты #4–#9 и #11. В `server-snapshot` уже есть код accounts, balances и account_id; это требует уточнения остаточного объёма P3/P5/P6, но не доказывает их завершение в production. Актуальные статусы — в `docs/BACKLOG.md`. PR #17/#18 остаются открытыми и не являются разрешением на применение изменений.

GitHub Issues — рабочий backlog. Этот файл задаёт порядок крупных инкрементов и зависимости.

## P0 — Production audit

Подтвердить фактическое состояние production перед дальнейшей разработкой:
- актуальные backend/frontend файлы;
- реально доступные API;
- наличие/отсутствие `prompt()` / `confirm()`;
- текущую конфигурацию production-доступа;
- расхождения между production и repository snapshot.

Результат: обновлённый `docs/CURRENT_STATE.md`.

## P1 — UI v2.1: управление структурой статей

Цель: полноценное управление группами, подгруппами и статьями через React UI.

Включает:
- создание;
- переименование;
- безопасное удаление;
- собственные modal dialogs;
- понятные ошибки зависимостей;
- регрессионную проверку календаря и entries.

Не смешивать с глобальным redesign календаря.

## P2 — UI v2.2: платёжный календарь

После P1:
- выходные визуально выделяются, но остаются кликабельными;
- выделение текущего дня;
- selected cell;
- сохранение выбранного месяца;
- улучшение отображения нескольких entries;
- улучшение entry modal;
- sticky/scroll UX.

## P3 — Financial core v1: остатки

Добавить:
- начальный остаток;
- движение за день;
- остаток на конец каждого дня;
- прогноз будущего cash balance.

Бизнес-правило: пользователь может начать работу в середине года, внеся начальный остаток на 1 января и вручную заполнив необходимые прошедшие месяцы.

## P4 — Cash gaps

На основе расчёта остатков:
- определять отрицательный прогнозный остаток;
- показывать размер дефицита;
- визуально выделять проблемные даты/периоды;
- не переносить платежи автоматически.

## P5 — Accounts and transfers

Добавить:
- счета;
- остатки по счетам;
- привязку операции к счёту;
- внутренние переводы;
- company-wide и per-account представление.

Перевод между собственными счетами не является доходом или расходом компании.

## P6 — Extended payment fields

Расширить entry:
- account;
- counterparty;
- project;
- comment.

Требует миграции БД и отдельного rollback plan.

## P7 — Structure UX

После базового CRUD:
- reorder;
- move;
- hide/archive;
- drag-and-drop;
- безопасная стратегия удаления с переносом данных как отдельная будущая задача.

## P8 — Analytics

После стабилизации financial core:
- доходы/расходы за период;
- структура расходов;
- cash-flow;
- динамика остатков;
- аналитика по проектам/контрагентам/счетам;
- экспорт.

## Общие правила

Каждый issue должен содержать:
- Goal;
- Current state;
- Required changes;
- Constraints;
- Acceptance criteria;
- Regression checks;
- Deployment notes.

Агент не должен брать задачу, если acceptance criteria или продуктовые решения не определены.
