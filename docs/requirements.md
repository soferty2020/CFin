# CFin — Требования (фактические)

## 1. Контекст

CFin — уже развёрнутый и работающий веб-сервис компании «Калипсо» для управления денежными потоками. Развитие идёт инкрементально поверх существующего кода в `/srv/cfin`. Серверная версия — source of truth.

**Стек (фактический):** React 19 + TypeScript + Vite 6 | Node.js 22 + Express + TypeScript | PostgreSQL 16 | Docker Compose | Nginx

---

## 2. Текущее состояние (MVP)

### Реализовано

- Авторизация: login + password, cookie-сессии (`cfin_session`, HttpOnly, Secure, SameSite=Strict), scrypt-хэширование.
- Справочники: группы → подгруппы → статьи (создание, переименование, удаление).
- Платёжный календарь: навигация по месяцам, таблица «статьи × дни», строки Доход/Расход.
- Финансовые записи (entries): добавление, редактирование, удаление; несколько записей в одной ячейке.
- Агрегация: сумма и количество записей в каждой ячейке календаря.
- Визуальное выделение выходных (`.weekend`) и текущего дня (`.today`).

### Не реализовано

- Остатки по счетам, прогноз, кассовые разрывы.
- Счета и переводы между ними.
- Отчёты, аналитика, экспорт.
- Контрагенты и проекты.
- Регулярные операции.
- Управление справочниками через модальные окна (сейчас — `prompt()`/`confirm()`).

---

## 3. Ближайший инкремент: UI v2.1

### Цель

Полноценное управление группами, подгруппами и статьями через собственные модальные окна, без `prompt()`/`confirm()`.

### Требования

1. **Создание группы** — модальное окно с полем «Название», кнопка «Создать».
2. **Создание подгруппы** — модальное окно с полем «Название», привязка к группе автоматическая.
3. **Создание статьи** — модальное окно с полем «Название», привязка к подгруппе автоматическая.
4. **Переименование** — модальное окно с предзаполненным полем, кнопка «Сохранить».
5. **Удаление** — модальное окно подтверждения с понятным сообщением. При серверном отказе (409) — показать текст ошибки.
6. **Без `prompt()`/`confirm()`** — все диалоги через React-компоненты.

### Backend — готов

PATCH `/api/categories/:kind/:id` и DELETE `/api/categories/:kind/:id` уже реализованы в `index.ts`. Фронтенд уже вызывает их — нужно только заменить способ ввода/подтверждения.

### Definition of Done

1. Создать тестовую группу через модальное окно (без `prompt()`).
2. Создать в ней подгруппу.
3. Создать статью.
4. Переименовать статью, подгруппу и группу.
5. Удалить пустую статью.
6. Убедиться, что статью с записями удалить нельзя (сервер возвращает 409, UI показывает ошибку).
7. После reload изменения сохраняются в PostgreSQL.
8. Login продолжает работать.
9. Calendar продолжает работать.
10. Несколько записей в одной ячейке продолжают работать.
11. Редактирование и удаление финансовой записи продолжают работать.
12. Выходные дни остаются кликабельными и визуально выделенными.
13. Docker build проходит успешно.

## 5. Дальнейшая финансовая логика

| Этап | Содержание |
|------|------------|
| Остатки | Начальный остаток на 1 января; ежедневные остатки; текущие деньги = остаток на конец вчерашнего дня |
| Прогноз | Операции на сегодня входят только в прогноз |
| Переводы | Простая операция «Перевод» между счетами, не доход/расход |
| Кассовые разрывы | Определение по общему остатку компании |
| Регулярные записи | Выбор «только эта дата / все будущие» |
| Аналитика | По статьям, контрагентам, проектам, счетам |
| Сравнение периодов | Неделя, месяц, квартал, год, произвольный диапазон |
| Экспорт | Календарь и отчёты в Excel |

## 6. Справочники — принятые бизнес-решения

- Структура статей создаётся пользователем с нуля: группа → подгруппа → статья.
- Статью можно создавать, переименовывать, менять порядок, переносить, скрывать.
- Одна статья может содержать и доходы, и расходы.
- Контрагент: поиск по названию, создание из формы; тип — клиент, поставщик, сотрудник, другое.
- Проекты: в одном справочнике, тип — клиентский или внутренний.
- Неактуальные контрагенты и завершённые проекты скрываются из нового выбора, но остаются в истории.
- Порядок групп, подгрупп, статей — drag-and-drop.
- Все дни календаря показываются; выходные и праздники визуально выделяются.

---

## 7. Защита данных

- Группу нельзя удалить, если есть подгруппы.
- Подгруппу нельзя удалить, если есть статьи.
- Статью нельзя удалить, если есть записи.
- Каскадное удаление — только с отдельного согласования.
- Frontend показывает понятную ошибку при серверном отказе.

---

## 8. Backup и deployment

- Перед каждым значимым инкрементом: получить актуальные серверные файлы.
- Backup изменяемых файлов в `/srv/cfin/backups/`.
- При риске для данных — `pg_dump`.
- Docker build → `docker compose up -d --no-deps` → smoke-test.
- Старый backup не удалять до подтверждения результата.

---

## 9. Принципы работы

1. **Сервер — source of truth.** Перед инкрементом — актуальные файлы с сервера.
2. **Инкрементальность.** Небольшие завершённые изменения.
3. **Сохранение данных.** Никакого каскадного удаления без согласования.
4. **Безопасность.** Не выводить `.env`, пароли, токены, ключи, cookie.
5. **Пользователь предпочитает** готовые изменённые файлы, а не инструкции по ручному редактированию.
